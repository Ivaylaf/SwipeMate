SwipeMate - инструкции за стартиране и предаване
=================================================

1. Кратко описание
------------------
SwipeMate е мобилно приложение за групово вземане на решения чрез swipe-базиран интерфейс. Потребителите могат да създават сесии с приятели, да задават филтри по категория и да гласуват по предложения. При общо одобрение се записва съвпадение в историята.

2. Съдържание на проекта
------------------------
Основните части на проекта са:
- SwipeMate.sln - Visual Studio solution файл;
- SwipeMate.Api - backend част, разработена с ASP.NET Core Web API;
- SwipeMate.Mobile - мобилно приложение, разработено с .NET MAUI;
- render.yaml - конфигурация за Render hosting;
- Presentation - презентация към дипломния проект;
- readMe.txt - този файл с инструкции.

3. Онлайн версия
----------------
Backend частта е публикувана онлайн чрез Render:
https://swipemate-api.onrender.com

Базата данни е PostgreSQL и е разположена в Supabase. Мобилното приложение е настроено да използва онлайн backend адреса автоматично, затова за демонстрация не е необходимо да се стартира локално API проектът.

Важно: при безплатния план на Render първата заявка може да се забави, ако услугата е била неактивна. При първо влизане или регистрация е нормално да се изчака около 30-60 секунди.

4. Инсталиране на приложението чрез APK
---------------------------------------
1. Отваря се QR кодът или линкът към APK файла.
2. Файлът SwipeMate.apk се изтегля на Android устройство.
3. Ако Android поиска разрешение за инсталиране от външен източник, разрешава се само за текущата инсталация.
4. Стартира се приложението SwipeMate.
5. Регистрират се два потребителски акаунта или се използват вече съществуващи.

5. Администраторски акаунт
--------------------------
За демонстрация е наличен административен акаунт:

Потребителско име: admin
Парола: Admin123!

Администраторът може да преглежда потребители, да вижда детайли за профили, да блокира и отблокира потребители, както и да активира или деактивира каталожни предложения.

6. Демонстрационен сценарий
---------------------------
Препоръчителен сценарий за представяне:
1. Вход или регистрация с два отделни потребителски акаунта.
2. Добавяне на приятел чрез търсене по потребителско име или имейл.
3. Приемане на заявката за приятелство от втория акаунт.
4. Създаване на сесия от първия акаунт.
5. Избор на приятел и задаване на филтри.
6. Приемане на поканата от втория акаунт.
7. Добавяне на филтри и от втория участник.
8. Гласуване с бутоните за одобрение и отказ.
9. Преглед на получено съвпадение в историята.
10. Преглед на профил, постижения и административен панел.

7. Основни функционалности
--------------------------
- регистрация и вход;
- редакция на потребителски профил;
- запазване на сесия след вход;
- добавяне на приятели;
- групови покани за сесия;
- филтриране по категории: филми и сериали, ресторанти, рецепти и настолни игри;
- обединяване на филтрите между участниците;
- swipe-базирано гласуване;
- записване на съвпадения;
- история на сесии и съвпадения;
- администраторски панел;
- export/backup на основни данни.

8. Стартиране на проекта във Visual Studio
------------------------------------------
Необходими програми:
- Windows 10/11;
- Visual Studio 2022;
- .NET 9 SDK;
- .NET MAUI workload;
- Android Emulator или Windows Machine target;
- интернет връзка.

Стъпки:
1. Отваря се SwipeMate.sln във Visual Studio 2022.
2. Като startup project се избира SwipeMate.Mobile.
3. Избира се Android устройство/емулатор или Windows Machine.
4. Натиска се Start.

При този вариант приложението използва публикувания онлайн backend адрес.

9. Локално стартиране на backend при нужда
------------------------------------------
Локално стартиране не е необходимо за демонстрация, но е възможно при разработка:
1. Стартира се PostgreSQL база данни.
2. В SwipeMate.Api/appsettings.Development.json се задава локален connection string.
3. Като startup project се избира SwipeMate.Api.
4. Стартира се API проектът.
5. Локалният адрес за Windows е http://localhost:5274.
6. Локалният адрес за Android Emulator е http://10.0.2.2:5274.

10. Backup/export на базата
---------------------------
В административния панел има възможност за JSON export на основните данни. Експортът не включва паролни хешове.

За пълен backup на PostgreSQL базата може да се използва Supabase export или pg_dump.
